# Datathon preparation

The user authorized a tabular data workflow, EDA, a baseline, quality evaluation, launch verification, documentation, and publication. The user also explicitly approved isolated pandas, scikit-learn, and matplotlib dependencies on 2026-10-16.

## Design

Use a standalone local Python CLI in `datathon/`. This keeps data work independent of Docker, AI credentials, authentication, and the RAG service. A notebook-only workflow is less reproducible, and a browser upload feature would spend preparation time on API/UI integration before the competition task is known.

Support CSV/TSV and JSON records/JSONL. Require an explicit classification or regression task and target column. Validate schema and targets, exclude declared ID/group/time/drop columns from features, split before fitting preprocessing, and compare a linear model with a dummy baseline. Random classification splits are stratified; optional group and chronological splits address entity/time leakage. Report the split and its limitations rather than implying an unbiased final test score.

EDA produces missing-value, type, duplicate, distribution, and correlation summaries with matplotlib charts in a standalone escaped HTML report. Runs save JSON metrics, validation predictions, split membership, source SHA-256, dependency versions, and configuration. Optional unlabeled prediction preserves the ID/order and refits the selected model on labeled rows after evaluation. Inputs and outputs stay ignored. No automatic external API calls or model deserialization is needed.

## Acceptance

`bun run datathon:demo` completes both synthetic tasks without an LLM, Docker, or downloaded datasets. `bun run datathon:test` proves the data/evaluation boundaries. Real data can be supplied through documented CLI arguments. Outputs never overwrite an existing nonempty run directory. No private dataset or generated report is staged. Synthetic demo scores are labeled as synthetic and are never presented as contest results.
